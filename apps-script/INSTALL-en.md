# Wissensbau for Google Apps Script

A standalone, Drive-backed replacement for the simplified Wissensbau workflow. Runtime code is plain JavaScript in `.gs` files plus HTML/CSS/browser JavaScript in `.html` files. There is no Python process, Node server, npm runtime dependency, external database or external font request.

The app provides workspace setup, uploads and Google-file imports, incremental wiki compilation, versioned Markdown output, exact-title links, keyword search, source-first chat, conversation history, connections, mechanical wiki-health checks, build history and API settings. The English and German UI uses the same Sora/Inter fonts as the existing app; font data is embedded and licenses are included.

This is a new deployment target, not an in-place replacement of the existing Express/Python installation. Existing project files and `data/raw/` are untouched. Python research/evaluation utilities, local password administration and IMAP/SQL connectors are not runtime dependencies or features of this Drive-native app. Google identity replaces the local login system. No Google deployment or real-provider validation has been performed from this development environment.

## Install using the Apps Script editor

The easiest package is `dist/Wissensbau-AppsScript.zip`, generated by `npm run package` in this directory. Its `Code.gs` combines all server modules, so installation needs only one script file.

1. Create a standalone project at [script.google.com](https://script.google.com/). Name it **Wissensbau**.
2. Replace the default `Code.gs` with the package's `Code.gs`.
3. Add HTML files named **Index**, **Styles**, **Fonts**, **Translations**, and **Client**, and paste the corresponding `.html` contents. Apps Script adds the extension automatically.
4. In **Project Settings**, enable showing `appsscript.json`; replace its contents with the package manifest.
5. Under **Services**, add **Drive API v3** with identifier `Drive`. If using a standard Google Cloud project, enable its Google Drive API as well.
6. Select **Deploy → New deployment → Web app**. Execute as **User accessing the web app** and initially allow **Only myself**. Keep these identity settings: running as the owner while allowing other people access would change the intended per-user isolation.
7. Authorize the application and open the deployment URL. Create a workspace. The optional folder field selects a parent for a *new* Wissensbau subfolder.
8. Add sources, run **Build wiki**, and try source search and chat. Both work without a model API key.
9. To use AI, open **Settings**, enter an OpenAI-compatible HTTPS base URL, a model name and your own API key. Enable compilation and/or generated chat answers separately. Save before starting another build.

Use the modular `src/` files **or** the combined package, not both in one Apps Script project. Duplicating both creates duplicate server definitions.

## Install using clasp

Install Google's [clasp](https://github.com/google/clasp) separately and authenticate it. For an existing empty script project, copy `.clasp.json.example` to `.clasp.json`, enter the script ID, leave `rootDir` as `src`, and run `clasp push`. Enable the Apps Script API in your account when clasp requests it. Use the editor's deployment steps above afterward.

`.claspignore` patterns are relative to `rootDir`. They include only `.gs`, `.html` and the manifest. Do not commit your authenticated clasp credentials. The generated package also contains a project-content JSON body for the official Apps Script `projects.updateContent` API; it is not an authentication token and does not publish a deployment.

## Storage

```text
Wissensbau/
  workspace.json       IDs of this workspace's folders
  settings.json        preferences; never contains the API key
  active.json          pointer to the last fully published version
  job-pointer.json     pointer to the current/last build
  inbox/               uploaded or copied source files; readers never overwrite them
  builds/<build-id>/
    job.json           durable progress/checkpoints
    <topic>.md         generated or source-derived Markdown
    index.md           map of content
    snapshot.json      extracted source text, topic data, pages and exact-name entities
  cache/               cached model responses keyed by prompt/model/endpoint
  chats/               one JSON file per conversation
  scratch/             temporary Google conversions
```

The workspace ID and optional API key are stored in **User Properties**. These are the two deliberate exceptions to Drive storage: locating the workspace without an external database, and keeping the API key out of ordinary Drive files. Keys are never included in bootstrap responses, page HTML, snapshots or chat history. Treat the Apps Script project and its editors as trusted: project editors can change the code.

Drive files are private according to the parent folder's actual permissions. The app does not make files public. If you choose a shared parent, its inherited access still applies. Imports make copies, not a live synchronization connection. Edit the inbox copy or reimport to include later changes to an external original. Local `.gdoc`/`.gsheet`/`.gslides` reference files are an exception: they read the referenced live file when built.

## File coverage

| Input | Extraction |
|---|---|
| DOCX, DOCM, DOTX, DOTM | Paragraph/run text, tables, tabs, headers, footers, footnotes/endnotes; no macro execution |
| XLSX, XLSM, XLTX, XLTM | All worksheets in workbook order; shared/inline strings, sparse cells, booleans, common dates and cached formula values |
| PPTX, PPTM, PPSX, PPSM, POTX, POTM | Slides in presentation order, shape/table text, speaker notes; no macro execution |
| Google Docs | Native text, including document tabs and child tabs |
| Google Sheets | All worksheets' displayed cell values |
| Google Slides | Shape/table/group text and speaker notes |
| ODT, ODS, ODP | OpenDocument paragraphs, table values or slide text from the ZIP/XML container |
| PDF; DOC/DOT, XLS/XLT/XLSB, PPT/PPS/POT; RTF | Attempt temporary Google conversion, if enabled. Actual support depends on Google's importer and the document; failures are reported |
| TXT, Markdown, CSV/TSV, JSON, XML, HTML, YAML, logs | Text; HTML scripts/styles and tags are stripped |
| EML | Headers and decoded text bodies; MIME attachments are not expanded into independent sources |
| ZIP | File manifest only; no recursive import |
| Image/audio/video | Filename metadata only; no image interpretation or transcription API call |

This is not a renderer for every Microsoft product. Access databases, OneNote notebooks, Outlook PST archives, encrypted documents, embedded objects, chart text, image text in Office files and all Excel number-format variants are not fully supported. Spreadsheet formulas are **not executed**: cached values are used, and missing caches are explicitly marked. Use native Google conversion or a text/modern Office export when the direct reader is insufficient. PDF conversion can invoke Google's OCR and must be checked against the original; this is independent of the configured LLM API.

## Processing modes

“Local” here means processing without a model provider, not offline/on-device processing: Apps Script and Drive still run on Google servers and require network access.

**Local (default):** JavaScript reads sources, creates one source-oriented topic per filename, preserves source text, adds references and exact-title links, and retrieves excerpts with BM25. It does not perform semantic topic inference, summarization, translation, embedding calls, model reranking or generated answers.

**API-assisted compilation:** topic/entity extraction and page writing use the configured OpenAI-compatible API. Model responses are cached in Drive. Links, references, state, exact-name identity matching and search still use JavaScript. Source text is treated as data, never executable instructions. This does not eliminate prompt-injection or hallucination risks; generated pages remain visibly labeled.

**API-assisted chat:** keyword retrieval happens first; only the chosen excerpts and the question are sent to the model. Conversation history is stored for reading but is not used to rewrite follow-up questions. Ask standalone questions for reliable retrieval. Citations identify the supplied excerpts; they do not prove generated claims.

Both API options are off until explicitly enabled. The app never calls a model merely to read an image or to list sources. Pattern redaction catches only some recognizable secrets and SSNs/IPs. It is not a full privacy filter and does not remove names or all personal information. Prompts, cached responses and snapshots may contain sensitive source data.

## Resumable builds and limits

Each execution advances at most 20 work units within a target budget of 150 seconds. Progress is saved after each unit. The open UI continues in batches; after closing it, use **Continue build** or enable the optional time trigger. A provider request or Google conversion can itself take longer than the target budget; Apps Script's hard execution limit can still interrupt it. Resume retries the incomplete unit, with successful model responses retrieved from cache.

Cancellation is observed between units; an in-flight Google/API request cannot be interrupted. An unsupported/unreadable source makes the build fail instead of silently omitting it. A failed or stopped build retains the existing published version. A final file-ID/modified-time check rejects sources changed during the build. Partial outputs remain in their build folder for inspection and are never selected by `active.json`.

Initial application bounds: 500 source files, 10 MB per uploaded/read binary file, one million extracted characters per source, eight million characters per corpus, 200,000 cells per spreadsheet, 4,000 ZIP entries and 40 MB total declared/unpacked ZIP content, 60,000 prompt characters, 32 MB per persisted state/snapshot file, 100 messages per conversation. Native Google files use the text/cell limits rather than the binary size limit. Source and API quotas can be reached before these bounds. Large collections should be split into separate workspaces/projects. No claim of production-scale performance is made.

Historical builds, chats, cached responses and exports use Drive space; remove unwanted older folders manually in Drive. Do not remove the folder referenced by `active.json`. A hard-terminated conversion may leave a temporary file in `scratch/`; it can be removed there. Deployment as a public multi-tenant product needs a separate OAuth/permission review; this package starts as a personal deployment.

## Verification

From this directory, with Node 20+ installed for **development only**:

```sh
npm run check
npm test
npm run package
```

No npm install is needed for those commands. Tests run pure JavaScript plus an in-memory simulation of Drive, Properties, Google document services, locks, triggers and API responses. They use actual ZIP/XML structures to exercise Office readers, resumable compilation, reference output, failed builds, publication, cancellation, source edits, cache behavior and key isolation. Simulation is not a substitute for a real deployment/authorization check.

`node scripts/preview.cjs` is an optional repository QA tool that uses the existing frontend Playwright installation and local Chrome. It renders synthetic data, takes desktop/mobile/German screenshots and checks for browser errors. It is not included in the deployable runtime.

## Shared core

`src/Core.gs` contains no Google service calls. It can also be loaded with CommonJS in Node, or used as the `WikiCore` global in another JavaScript runtime. `npm run package` emits the same code as `dist/WikiCore.js`. `Store.gs`, `Readers.gs` and `Compiler.gs` provide the Apps Script adapters and execution loop.
